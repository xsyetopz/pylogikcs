# Logic Pro `.logikcs` 文件格式

从 Logic Pro 12.3 `Default.logikcs` 逆向得出。

## 封装

`.logikcs` 是 Apple 属性列表 (plist) XML 文件，版本 1.0。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN"
  "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0">
<dict>
    <key>Content</key>
    <string>com.apple.logic.keycommand</string>
    <key>Version</key>
    <string>12.3.0</string>
    <key>KeyCommandColors</key>
    <dict>…</dict>
    <key>KeyCommandShortNames</key>
    <dict>…</dict>
    <key>LogicBinaryPreferences</key>
    <data>…</data>
    <key>TouchBarAssignments</key>
    <data>…</data>
</dict>
</plist>
```

默认预设中未观察到其他顶层键。

## 顶层键

### `Content`（字符串）

始终为 `"com.apple.logic.keycommand"`。标识文件类型。

### `Version`（字符串）

生成该预设的 Logic Pro 版本，如 `"12.3.0"`。

### `KeyCommandColors`（字典）

将**用户可见的命令 ID**（字符串键，十进制）映射到颜色索引（整数）。颜色索引范围为 1–7。

默认预设中存在一个异常键：`"New Child"` -> `""`（空字符串）。其用途未知；
可能是编辑器状态的残留条目。

默认预设中观察到的键：62 个（含异常条目），值 1–7。

### `KeyCommandShortNames`（字典）

将**用户可见的命令 ID**（字符串键，十进制）映射到简短显示名称（字符串）。
这些是 Logic Pro 快捷键窗口中显示的缩写名称。

默认预设中观察到的键：33 个。示例：

| 命令 ID | 简称 |
| --- | --- |
| `1012` | `Rd/Off` |
| `2000` | `MIDI` |
| `2002` | `Audio` |
| `2004` | `Aux` |

### `LogicBinaryPreferences`（二进制数据）

Base64 编码的二进制数据。核心快捷键绑定表。详见下文。

### `TouchBarAssignments`（二进制数据）

Base64 编码的 **zlib 压缩**二进制数据。解压后为 30000 字节的稀疏查找表
（默认预设中 5102 个非零条目）。内部结构尚未完全逆向。在 macOS 上，此数据
将 Touch Bar 按钮位置映射到 Logic 功能。

---

## `LogicBinaryPreferences` 二进制格式

### 概览

```mermaid
flowchart LR
    BLOB["解码后 43,170 字节"] --> HEADER["头部<br/>684 字节"]
    HEADER --> RECS["记录区域<br/>201 条记录 × 6 字节<br/>（偏移 0x02ac–0x7206）"]
    RECS --> TRAILER["尾部<br/>13,980 字节"]
```

二进制数据包含三个区域：

1. **头部**（字节 0x0000–0x02ab，684 字节）——带键的元数据。包含单字符 ASCII
   键（`L`、`R`、`r`、`C`、`K`、`*`、`c`、`p`、`s` 等），后跟短整数或字符串值。
   可能编码了段长度、版本标记或内部查找表。

2. **记录区域**（字节 0x02ac–0x7205，1206 字节）——201 条 6 字节快捷键绑定记录，
   每条以哨兵 `0xF7 0x00` 结尾。

3. **尾部**（字节 0x7206–末尾，13,980 字节）——大部分为零，含 247 个稀疏非零字节。
   用途未知；可能是为未来快捷键绑定槽位预留的固定大小缓冲区。

### 记录结构

每条记录恰好 6 字节：

```text
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│  byte 0  │  byte 1  │  byte 2  │  byte 3  │   0xF7   │   0x00   │
├──────────┴──────────┼──────────┴──────────┼──────────┴──────────┤
│     载荷 A          │     载荷 B          │     哨兵            │
│     (u16 LE)        │     (u16 LE)        │                      │
└─────────────────────┴─────────────────────┴─────────────────────┘
```

4 字节载荷编码两个 16 位小端字。语义映射取决于记录**子类型**。

#### 记录子类型 A —— 快捷键绑定

最常见的子类型。`载荷 A` 为**按键分配**；`载荷 B` 为**内部命令索引**。

```text
载荷 A (u16 LE) = [key_code: 高 8 位] [flags: 低 8 位]
载荷 B (u16 LE) = internal_command_index（大端序语义未确认）
```

- `key_code` —— Apple 虚拟键码（Carbon `kVK_*` 常量）。默认预设中观察到的值：

  | 值 | Carbon 常量 | 按键 |
  | --- | --- | --- |
  | `0x00` | `kVK_ANSI_A` | A |
  | `0x01` | `kVK_ANSI_S` | S |
  | `0x02` | `kVK_ANSI_D` | D |
  | `0x03` | `kVK_ANSI_F` | F |
  | `0x28` | — | ( |
  | `0x29` | — | ) |
  | `0x2b` | `kVK_ANSI_Comma`? | + |
  | `0x2c` | — | , |
  | `0x2d` | — | - |

  部分映射到标准 Carbon 虚拟键码；其他（0x28–0x2d）直接对应 ASCII 码点，
  表明 Logic 使用了混合映射。

- `flags` —— 修饰键位掩码。默认预设中 201 条记录的 `flags` 均为 `0x00`
  （无修饰键）。修饰键常量未确认，但可能对应 Carbon 事件标志（如
  `cmdKey=0x08`、`shiftKey=0x02`、`optionKey=0x04`、`controlKey=0x01`）。

- `internal_command_index` —— 标识 Logic 功能的整数。这些**不是**
  `KeyCommandColors` 或 `KeyCommandShortNames` 中的用户可见命令 ID。内部索引
  与用户可见 ID 之间的映射尚不清楚。

#### 记录子类型 B —— 内部查找

少数记录的载荷值在按子类型 A 解释时会产生不合理的命令索引（>10000）。
这些可能是内部查找表或元数据记录，而非用户可编辑的快捷键绑定。默认预设示例：

| 原始载荷 | LE 字 A | LE 字 B | 备注 |
| --- | --- | --- | --- |
| `1c 20 00 02` | 8220 | 512 | 每组 3–4 条；byte 0 递增 |
| `1d 20 00 03` | 8221 | 768 | |
| `1e 20 00 00` | 8222 | 0 | |

这些记录以 3–14 条为一组出现在不同偏移位置。每组内第一个字节单调递增
（`0x1c`->`0x1d`->`0x1e`->`0x1f`），暗示为索引条目。

### 记录统计（默认预设，201 条记录）

| 属性 | 数量 |
| --- | --- |
| 总记录数 | 201 |
| 唯一 `载荷 A` 值 | 59 |
| 唯一 `载荷 B` 值 | 59 |
| 唯一 key_code 值 | 9 |
| 唯一 flags 值 | 1（`0x00`） |
| key_code 在 0x00–0x03 范围的记录 | 168（83%） |
| key_code 在 0x28–0x2d 范围的记录 | 33（16%） |

### 记录排序

记录不按命令索引或键码排序。相同命令索引的记录连续分组。顺序似乎遵循
Logic 的内部命令注册顺序。

### 头部区域（字节 0x0000–0x02ab）

684 字节的头部包含带单字符 ASCII 键的元数据。非零数据呈带状分布：

```hex
0x01c6:  4c 00 00 00 00 01     "L" + 5 字节值
0x01cc:  2c 00 00 00 00 01     "," + 5 字节值
0x01d2:  52 00 00 00 00 01     "R" + 5 字节值
0x01e0:  72 00 00 72 00 00     "r\0\0r\0\0"
0x01e6:  43 00 00 00 00 01     "C" + 5 字节值
0x01ec:  2e 20 00 2e 00 00     ". .\0.\0\0"
...
0x020c:  63 00 00 63 00 00     "c\0\0c\0\0"
0x0212:  70 2c 00 70 00 00     "p,\0p\0\0"
0x0218:  73 04 00 73 00 00     "s\x04\0s\0\0"
0x022a:  4b 00 00 00 00 01     "K" + 5 字节值
0x0230:  2a 00 00 00 00 01     "*" + 5 字节值
```

头部可能编码了：

- 段或表长度（`L`、`R`、`C`、`K`）
- 内部数据指针或计数
- 部分记录数据的第二份副本（`r`、`c`、`p`、`s` 条目镜像了部分快捷键绑定记录）

### 尾部（字节 0x7206–末尾）

13,980 字节，大部分为零。247 个非零字节分散分布。尾部可能是为未来快捷键
绑定分配的固定大小空间，或编码了某些在默认预设中大部分为空的数据。

---

## `TouchBarAssignments` 格式

- 压缩：zlib (RFC 1950)，294 字节 -> 30,000 字节解压
- 结构：16 位条目（小端序）的稀疏数组
- 每个条目位于固定的 6 字节步长位置（30,000 / 5,000 = 每槽 6 字节）
- 观察到的条目大多为 `0x0002`，偶尔有 `0x0005` 等值
- 可能编码：`[Touch Bar 槽位索引] -> [内部功能 ID]`

```mermaid
flowchart LR
    B64["base64 字符串"] --> ZLIB["zlib 解压"]
    ZLIB --> ARRAY["30,000 字节<br/>5,000 槽 × 6 字节"]
    ARRAY --> SLOT["slot[i] = 偏移 i×6 + 4 处的 u16 LE"]
```

每个 6 字节槽：4 字节零填充 + 2 字节（u16 LE）功能索引。

---

## 用户可见命令 ID 与内部索引

存在两套独立的 ID 空间：

| 空间 | 使用位置 | 示例 |
| --- | --- | --- |
| 用户可见命令 ID | `KeyCommandColors`、`KeyCommandShortNames` | `1012` -> `"Rd/Off"` |
| 内部命令索引 | `LogicBinaryPreferences` 记录载荷 | `11`、`12`、`28`、`2059`、`2076` |

两套空间之间的映射尚未逆向。头部区域可能包含此映射。

## 头部区域 — 键值条目

684 字节的头部包含两份键绑定表的镜像副本（副本 1：~0x01c8–0x0260，副本 2：~0x3384–0x3420）。每条目 4 字节：

```
┌──────────┬──────────┬──────────┬──────────┐
│  byte 0  │  byte 1  │  byte 2  │  byte 3  │
├──────────┼──────────┼──────────┼──────────┤
│ key_code │  flags   │   0x00   │ key_code │
│ (ASCII)  │          │（保留）   │ （重复）  │
└──────────┴──────────┴──────────┴──────────┘
```

- **key_code** — 按键产生的未修饰字符（ASCII）。大写字母以小写存储
  （如 `'P'` → `0x70` `'p'`）。
  编码方式为混合编码：

  | 范围 | 编码 | 示例 |
  |---|---|---|
  | `0x20`–`0x7e` | ASCII 可打印字符 | Space（`0x20`）、`'a'`（`0x61`）、`'-'`（`0x2d`） |
  | `0x00`–`0x1f`、`0x7f` | Apple Carbon `kVK_*` | Return（`0x24`）、Delete（`0x33`）、Escape（`0x35`）、Tab（`0x30`） |
  | `0x7b`–`0x7e` | Carbon 方向键 | 左（`0x7b`）、右（`0x7c`）、下（`0x7d`）、上（`0x7e`） |
  | `0x80`–`0xff` | 扩展 ASCII（特定语言环境） | 瑞典语 `'ä'`（`0xe4`）、`'å'`（`0xe5`）、`'ö'`（`0xf6`） |

  非英语预设（瑞典语、简体中文）使用高位字节编码特定语言环境的字符。
  瑞典语预设已验证：505 个键盘绑定与 `Swedish_clipboard.txt` 导出匹配。

- **flags** — 修饰键位掩码：

  | 值 | 修饰键 | 来源 |
  |---|---|---|
  | `0x00` | 无 | 默认预设，所有记录 |
  | `0x01` | Shift (⇧) | `Record_R_to_SHIFT_R.logikcs` |
  | `0x04` | Ctrl (⌃) | `Play_SPACE_to_CTRL_SPACE.logikcs` |
  | `0x08` | Opt (⌥) | `Play_SPACE_to_OPT_SPACE.logikcs` |
  | `0x20` | Cmd (⌘) | `Play_SPACE_to_CMD_P.logikcs` |

  多修饰键组合已通过 9 个语言预设的按位或运算确认：

  | 标志位 | 组合 | 示例命令 |
  |---|---|---|
  | `0x21` | Cmd+Shift | "Save Project as…" |
  | `0x25` | Cmd+Ctrl+Shift | "Unpack Take Folder…" |
  | `0x28` | Cmd+Opt | "Split Regions/Events…" |
  | `0x09` | Opt+Shift | "Open Tempo List…" |
  | `0x0d` | Opt+Ctrl+Shift | "Toggle Autopunch Mode"（德语） |
  | `0x2c` | Cmd+Opt+Ctrl | "Toggle Autopunch Mode"（法语） |

- **byte 2** — 观察到的条目中始终为 `0x00`。保留或填充。

- **byte 3** — byte 0 的重复。可能是校验和或对齐辅助。

头部还存在第二种条目格式：

```
┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────┐
│  byte 0  │  byte 1  │  byte 2  │  byte 3  │  byte 4  │  byte 5  │
├──────────┼──────────┼──────────┼──────────┼──────────┼──────────┤
│ key_code │   0x00   │   0x00   │   0x00   │   0x00   │   0x01   │
│ (ASCII)  │          │          │          │          │（哨兵）   │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
```

此 6 字节变体省略了 flags 字节和重复字节。它可能表示“已禁用”或“未分配”
状态的命令，或编码不同类型（单次按键命令与按键绑定分配）。末尾的 `0x01`
字节作为类型标记。

两种格式共存于头部。分配修饰键时，格式 B 条目会转换为格式 A。

## 未知项

1. 内部命令索引（f7 记录）到用户可见命令 ID 的映射
2. 记录子类型 B 的内部结构（约 20 条索引值异常的记录）
3. 6 字节头部条目格式（格式 B）的语义
4. 尾部的用途（13,980 字节，大部分为零）
5. Touch Bar 槽位到功能的映射
6. KeyCommandColors 中的 `"New Child"` → `""` 条目
7. 二进制格式在 Logic Pro 不同版本间是否变化
